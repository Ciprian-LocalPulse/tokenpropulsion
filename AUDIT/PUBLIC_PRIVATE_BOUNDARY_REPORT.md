# Public/private boundary report

Date: 2026-10-18. Internal post-implementation engineering audit, not third-party
certification. Scope: tracked public Core and public-site trees, static hosting bundle,
private-source separation, synthetic data provenance and latest publication controls.

## Repository boundaries

Public Core remains MIT and its v1/v2 tags and assets are preserved. The website is a
separate public repository. Enterprise additions are in a separately verified PRIVATE
repository; private source URLs, business plans, entitlement implementation and dashboard
records are deliberately absent from the public hosting bundle. Public MIT permissions
are not withdrawn and the private project composes the pinned public Core as a dependency.

## Executed checks

[evidence-ecosystem/boundary-check.json](evidence-ecosystem/boundary-check.json) records
tracked-file scanning, Python import AST checks, comparison against private source/business
file content hashes, and private synthetic-dashboard event-ID exclusion. No duplicated
private source, private imports, private dashboard IDs or high-confidence credentials
were detected in the public trees/bundle. A bare PEM header in historical Core security
fixtures is a test marker, not a private key; no key body is present.

Website packaging enforces an exact file allowlist and refuses unexpected stale files
or symlinks. It contains only HTML/CSS/JS, public JSON recordings, icons, poster, two
videos and captions. It excludes private siblings, production sources, build dependencies,
work files and internal dashboard data. Runtime code uses textContent and public GET
recordings; no prompt submission, provider key or private service exists in the website.

All five before/after examples were generated by actual Core Python calls. Complete CLI
stdout/input are retained; its heuristic counts are labeled separately from the exact
cl100k_base synthetic benchmark. No arbitrary user text is processed live. Video scenes
use actual CLI excerpts and the original published synthetic benchmark. No customers,
endorsements, production activity or provider billing results were fabricated.

## Security controls and limitations

Actions use least-privilege permissions and pinned official actions. Public site secret
scanning/push protection and vulnerability alerts are enabled; workflow defaults are
read-only. Private security feature availability is account/plan dependent and recorded
in the private security audit; repository visibility was never changed to bypass it.
No credentials are committed, and issuer secrets are generated ephemerally for local
demos. Pattern scanning and bounded tests cannot establish absence of every possible
secret, semantic leak, deployment misconfiguration or logging problem.

## Licensing and disposition

The public Core/site retain MIT notices. Private original additions carry a distinct
proprietary notice, with explicit acknowledgement that public MIT and third-party rights
remain intact. No third-party source or model checkpoint becomes exclusively owned.

Boundary checks passed within this scope. Enterprise is a research-alpha foundation,
not a production product. No live xAI call, private customer evaluation, SSO, durable
billing, complete penetration test or independent external audit is claimed.
